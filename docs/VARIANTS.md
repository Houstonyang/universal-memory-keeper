# 交付形态与取舍

记忆项目围绕同一组能力目标演进：核验原消息来源、区分成员与会话、管理本人事实的新旧版本，以及执行遗忘、禁记和本人解锁。不同运行环境对宿主改动、分发和接入方式的约束不同，因此形成配套版、市场版和通用版。

本仓库公开的是通用版源码。三种形态有不同的入口、存储与来源证据实现，不能视作同一份代码的三个安装包，也不承诺直接迁移运行时数据。

## 对比

| 维度 | 配套版 | 市场版 | 通用版（本仓库） |
| --- | --- | --- | --- |
| 主要用途 | 本地自用，与指定 QQ Agent 宿主配套 | 通过 QQ Agent 插件市场安装和更新 | 将记忆能力接入其他机器人框架或 Node 程序 |
| 宿主改动 | 插件配合宿主补丁 | 使用原版宿主扩展接口，不覆盖宿主源码 | 独立核心与服务，通过适配器接入 |
| 来源证据 | 配套宿主保留消息 ID、引用元数据和工具回执 | 插件核验原存档，并管理引用证据与完整回执；来源有歧义时不猜测 | 适配器提供原始事件字段，核心统一核验身份与事实来源 |
| 部署成本 | 需维护宿主版本与补丁的对应关系 | 依赖兼容的宿主插件 API 与已配置的机器人环境 | HTTP 路线需运行记忆服务并配置令牌；也提供 Node 模块入口 |
| 接入范围 | 配套 QQ Agent 实例 | QQ Agent 插件体系 | AstrBot、NoneBot2 + OneBot v11、Koishi 4、腾讯 botpy 接入代码 |
| 分发状态 | 本地保留配套实现 | 已在插件市场上架 | GitHub 开源源码 |
| 验证边界 | 配套宿主的验证结果仅适用于对应实现与版本 | 已有市场版本地自动检查及真实 QQ 验收记录，不推导为全部宿主版本兼容 | 0.1.1：58 项 Node 测试、22 项 Python 检查通过；真实框架/QQ/模型联调待补充 |

## 为什么保留三种形态

**配套版允许改动宿主，换取更直接的来源传递。** 补丁可以让历史消息和工具结果保留更完整的证据，但升级宿主后需要核对差异，不能把特定版本的文件快照当作通用补丁直接覆盖。

**市场版优先满足插件安装与更新的约束。** 在不修改宿主的前提下，插件负责接口自检、原消息匹配、引用证据与回执保存。无法唯一确认来源时拒绝猜测；绕过插件观测路径的行为不能被自动补齐为可信证据。

**通用版把宿主依赖放在适配器边界。** 核心独立管理身份、事实版本、禁记和存储，适配器负责把各框架事件转换为统一输入。代价是需要逐框架接入和验证；没有统一 AI 钩子的框架，还需要在 AI 插件中显式调用记忆接口。

AstrBot 首版在默认 LLM 请求钩子清空本次请求的旧上下文，只保留当前问题与经核验的本人记忆；这降低旧历史重新带回禁记内容的风险，也减少普通多轮闲聊上下文。其他插件或自定义调用链的额外注入需要另行核验。接入步骤见 [框架安装](ADAPTERS.md)。

## 使用数据与证据边界

截至 **2026-10-07**，维护者提供的插件市场统计为：记忆市场版于当日上架，当日下载量 **40+ 次**。这属于市场版的分发数据，不是本仓库的 GitHub 下载量，也不代表独立用户数、活跃用户数或通用版兼容性验证。

市场版本地保留了 1.0.2 的 289 项自动检查及 2026-10-07 的 10 轮真实 QQ 验收记录，覆盖写入、更新、遗忘、防复活、本人解锁、重启恢复与实际记忆检索。这里的版本指本地验收对象，不据此推定市场当前上架版本。原始聊天、账号、消息标识和私有验收材料不随本仓库公开。

通用版的可复现证据是仓库内的 [测试代码](../tests/)、[验证范围](VALIDATION.md) 和 [源码说明](SOURCE-GUIDE.md)。市场版的真实 QQ 验收不能替代通用版各框架的实际安装、消息事件与模型调用链验证。

## 仓库组织

当前公开仓库集中维护通用版核心、适配器、安装说明和测试；配套版保留在本地，市场版通过插件市场分发。这样可以让读者明确本仓库代码的适用范围，避免把不同交付形态的安装步骤和验证结果混用。

是否另行公开其他形态，应根据维护与分发需求决定。包含宿主补丁或已有市场渠道，本身不等于不能公开源码。
