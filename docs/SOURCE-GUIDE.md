# 源码说明

数据流：已认证平台事件 → 框架适配器 → `/v1/turn` → 身份/消息契约 → 原消息存储 → 策略核验 → 本人事实/维护回执 → 框架回复或模型请求。

| 文件 | 职责 |
| --- | --- |
| `core/contracts.mjs` | 框架、平台实例、机器人、会话类型、会话ID组成独立会话；原消息ID、原始毫秒时间、引用、转发、媒体须明确 |
| `core/engine.mjs` | 来源事实、事项归组、版本、过期、禁记、解锁；存储由构造参数注入 |
| `core/storage.mjs` | 原消息与维护状态分开原子持久化；损坏报错；不静默丢弃来源 |
| `core/runtime.mjs` | 本轮事件入口、明确事实规则、命令、本人检索范围；不允许用户参数替换当前发送者 |
| `server.mjs` | 环回 HTTP、Bearer 认证、请求大小和错误回执；完整JSON不做2000字符截断 |
| `clients/` | Python/Node 超时请求；不记录令牌、正文或私有ID |
| `adapters/` | 各框架的真实事件映射、入口和AI接入方式；客户端副本让适配器目录能独立安装 |
| `tests/` | 隔离合成事件、磁盘重载与真实环回HTTP测试 |

## 存储接口

核心 `ManagedMemory({sourceStore,stateStore,now})` 接收同步快照存储。`sourceStore.list(scope)` 返回原消息行；`stateStore.load(scope)` 返回 `{version,chatKey,facts,bans,controls}`；`save(scope,state)` 保存维护状态。运行入口另需要 `sourceStore.append(scope,row)`；默认 JSON 存储还提供 `recall(scope,mid)`。

调用 `note`/`control` 时再次查询原消息，核对发送者、正文和时间。HTTP 不暴露任意 `note(row)` 或覆盖 ownerId 的接口，维护动作只解析当前事件正文。鉴权令牌持有者是可信适配器，因此不要把服务令牌发给机器人聊天用户。

平台原ID可以为OpenID、UUID、有符号数字字符串。文件名是完整身份元组的SHA256，不由群号或用户可控路径直接拼接。发送者仍按平台真实身份隔离；不同平台的相同字符串不是同一人。不会自动合并跨框架记忆。

## 初版边界

召回限制为当前本人事实，不自动共享群成员事实。关键词召回不是向量语义检索；自动记忆采用明确规则，不推断任意偏好。原引用/转发/媒体消息可以保存来源，但不作为本人事实或本人维护授权。

核心支持撤回失效；目前各框架适配器没有自动订阅平台撤回通知，需宿主调用 `sourceStore.recall` 或后续新增对应通知映射。上线前需按实际平台验证时间字段：如果框架提供的是接收时间而非平台时间，回执也只能反映框架提供的时间，不会宣称捕获平台原始时间。

核心不是WebHook公网入口，不实施QQ公网回调签名验签。QQ官方桥只接已由腾讯SDK或已有验签宿主接收的消息；原始未验签HTTP JSON不能直接作为授权事件。
